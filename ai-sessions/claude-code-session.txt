  The task

  Build a single-page web app, with no login, where a person and an AI co-write
  a Markdown document. They describe it as "Google Docs meets AI pair-writing."
  You can use a prebuilt editor such as Tiptap rather than writing one from
  scratch.

  Required:
  1. The user can write and edit Markdown in the browser.
  2. The AI suggests changes to the whole document or to a selected part.
  3. Each suggestion shows as a visible diff before the user applies it.
  4. The user can accept, reject or refine each suggestion.
  5. It should feel like working with a co-author. They don't want a chatbot in
     a sidebar or something that writes the whole document by itself.

    clear.
  - How you used AI to build it: you shipped faster with AI and can explain your
    choices.
  - Code quality: the code is organized and readable enough for a teammate to

● The decisions are committed as 32ad94d. Here is the build plan.

  Build plan

  How it works

  - The user selects text and picks an action. The backend sends the model the
    whole document as context, but asks it to rewrite only the selection. So the
    AI acts as a co-author and doesn't write the whole doc.
  - The model returns the new text plus a short reason, for example "Cut filler
    words, merged two sentences."
  - The frontend diffs the old text against the new text with jsdiff and shows
    the changes inline in CodeMirror.

  API (backend)

  ┌─────────────────┬───────────────────────────────────────────────────────┐
  │    Endpoint     │                    Input → Output                     │
  ├─────────────────┼───────────────────────────────────────────────────────┤
  │ GET /models     │ → the list from LLM_MODELS, default first             │
  ├─────────────────┼───────────────────────────────────────────────────────┤
  │ POST            │ {document, selection, instruction, model, turns[]} →  │
  │ /suggestions    │ {replacement, reason}                                 │
  └─────────────────┴───────────────────────────────────────────────────────┘

  turns[] holds the earlier refine steps, so "now more formal" builds on the
  previous result.

  Errors: no key → 503 with a clear message. Rate limit → 429 with "try again".
  Provider failure → 502.

  Steps (one commit each)

  1. Backend AI endpoint. Config, a small LlmClient (httpx), /models,
     /suggestions and the prompt. Tests use a mocked provider, so tests never
     call Groq.
  2. Editor. CodeMirror with Markdown, an example document on first load so
     reviewers can try it right away, autosave to localStorage, and the model
     picker in the header.
  3. Selection popup. Improve / Shorter / Formal / custom instruction. While
     loading, the selection shows a "Rewriting…" state.
  4. Inline diff. Deleted words get a red strikethrough, inserted words show in
     green. Accept or reject each change, plus Accept all / Reject all. The
     suggested range is locked while the suggestion is open, so positions can't
     drift.
  5. Refine. A follow-up box on the suggestion card that sends the earlier
     turns, and the diff updates in place.
  6. History. Each accepted edit saves a snapshot to a side timeline, with view
     and restore.
  7. Polish and docs. Error states, keyboard shortcuts (Ctrl+Enter to accept,
     Esc to reject), the README sections, and the transcript export into
     ai-sessions/.

  ## 1. My mental model

  **How a suggestion flows**
  1. **Selection.** On every CodeMirror update, `useEditorAnchors.ts` measures
  the selection inside `requestMeasure`. It only does this when the selection
  holds more than whitespace and no suggestion is open.
  2. **Popup.** `Editor/index.tsx` shows `SelectionPopup` while
  `suggestion.state.status === "idle"`. Picking a quick action or typing a
  custom instruction calls `useSuggestion.request(action)`.
  3. **Request.** `request` trims whitespace from the range (`trimRange`), then
  dispatches `openSuggestion({from,to})` and collapses the selection. `run` then
  splits the doc into `before / selection / after` and calls `mutateAsync`
  (React Query `useMutation`, then `api/createSuggestion.ts`, then axios
  `shared/httpClient.post`).
  4. **Backend.** The chain is router → handler → `LlmClient`:
     - `suggestions_router.py` turns domain/LLM exceptions into HTTP errors.
     - `CreateSuggestionHandler.execute` checks the model against `LLM_MODELS`
  and builds messages with `prompt.build_messages`. The messages are: the system
  prompt, then a user message with the whole doc and the selection wrapped in
  `<selection>` plus the first instruction, then one assistant/user pair per
  refine turn.
     - `LlmClient.complete` sends an httpx POST to `{base}/chat/completions`
  with temperature 0.4. It maps 429 to `LlmRateLimitedError` and everything else
  to `LlmUnavailableError`.
     - `parse_completion` regex-extracts `<replacement>` (required) and
  `<reason>` (optional).
  5. **Diff.** The frontend runs `diffSegments(original, replacement)`, which is
  jsdiff `diffWordsWithSpace`. Adjacent added/removed parts are grouped into
  `change` segments, and two changes split by a gap of 2 words or fewer on the
  same line are merged. The result is dispatched with `showSuggestionDiff`.
  6. **Per-change decisions.** The ✓/✕ buttons live in `ChangeWidget` (a
  CodeMirror widget) and call `resolveChanges(view, status, id)` directly. When
  no change is still pending, it writes `resolveText(segments)` into the range
  in one transaction (`userEvent: "input.ai"`, `filter: false` to get past the
  range lock) and closes the suggestion.
  7. **History.** `useSuggestion.syncFromEditor` (from `onUpdate`) sees the
  `input.ai` transaction and calls `onApplied`. That calls
  `useHistory.record({kind:"ai-edit",...}, documentBefore)`, which also adds a
  "baseline" entry the first time.

  **Where state lives**
  - **CodeMirror `suggestionField`**: the range (mapped through edits and locked
  by a `changeFilter`), the phase, and the segments with their decisions.
  - **React**:
    - `useSuggestion`: request lifecycle (`idle/loading/ready/error`), the
  request with its turns and labels, and a mirrored `range`.
    - Anchors.
    - Document `content`.
    - Selected model.
    - History entries.
  - **localStorage**: `editor.document` (debounced 500 ms, flushed on
  `pagehide`), `editor.history` (30 entries max), `editor.model`.

  ## 2. Endpoints

  All wire fields are camelCase (via `BaseDataTransfer`). Error bodies are
  `{detail: string}`, or for 422 `{detail: [{loc,msg,...}]}`.

  **`GET /healthcheck`** (`bootstrap.py:95`)
  - Response: `200 {"status":"healthy"}`.
  - Every response carries an `X-Request-ID` header (echoed from the request, or
  generated).

  **`GET /models`** (`routers/models_router.py`)
  - Response: `200 {models: string[], default: string|null}`.
  - `default` is the first entry of `LLM_MODELS`.
  - No error cases. An empty config returns `{models:[], default:null}`.

  **`POST /suggestions`** (`routers/suggestions_router.py`)
  - Request:
    - `before`: string, default "", max 100k
    - `selection`: string, min 1, max 20k
    - `after`: string, default "", max 100k
    - `instruction`: string, 1 to 1k, must not be blank, gets stripped
    - `model`: string or null, optional
    - `turns`: list of `{instruction (1 to 1k), replacement (max 20k)}`, max 10
  - Response: `200 {replacement: string, reason: string|null, model: string}`.
  - Errors:

  | Status | When |
  |---|---|
  | 422 | Validation failed |
  | 400 | `UnknownModelError` |
  | 503 | `NoModelsConfiguredError`, or `LlmNotConfiguredError` (no key) |
  | 429 | `LlmRateLimitedError` |
  | 502 | `LlmUnavailableError` (timeout, network, provider 401/403/5xx,
  unexpected or empty body) or `MalformedSuggestionError` (no `<replacement>`
  tag) |
  | 500 | Anything else, with an opaque `"Internal server error"` |

  ## 3. Questions I still have

  **Architecture**
  1. Why does the open suggestion live in a CodeMirror `StateField`
  (`codemirror/suggestionField.ts`) and also get mirrored into React `range`
  state (`useSuggestion.ts:79,176`)? Could `SuggestionCard` read the field
  directly? What goes wrong if state lives only in React?
  2. `ChangeWidget` calls `resolveChanges` directly from the DOM
  (`suggestionField.ts:141`), and React only learns about it through
  `syncFromEditor`. Is it deliberate that CodeMirror owns this path and React
  just observes?
  3. The `README.md:62` diagram shows "prompt + tag parsing" in the backend. Why
  put tag parsing on the server instead of returning raw text and parsing on
  the client?

  **Backend and endpoints**
  4. `routers/models_router.py:9-19` defines a DTO inside the router and has no
  handler. The backend skill says router → handler, with DTOs in `use_cases`.
  Where is the line for when a use case is needed?
  5. Why does a provider 401/403 become 502 (`llm_client.py:74-75`, "rejected
  the API key") when a missing key gives 503? Both are configuration problems.
  6. `LlmClient.complete` opens a new `httpx.AsyncClient` per call
  (`llm_client.py:44`). Why not a shared client with connection pooling
  (lifespan / app.state)?
  7. The handler calls `get_configuration_variables()` directly
  (`create_suggestion_handler.py:19`), but `LlmClient` is injected with
  `Depends`. Why isn't config injected too? The tests have to monkeypatch the
  cached singleton (`test_suggestions_router.py:104`).
  8. Middleware order in `bootstrap.py:30,81`: `add_security_headers` is
  registered second, so it is the outer layer. On an unhandled exception, does
  the 500 response still get `X-Request-ID` and the security headers? Is the
  error logged twice, once as `request.failed` (line 52) and once as
  `unhandled_exception` (line 68)?
  9. `allow_credentials=True` (`bootstrap.py:24`). The app uses no cookies or
  auth, so why is it needed?

  **AI integration and prompt**
  10. `parse_completion` takes the first `<replacement>` match (`prompt.py:65`).
  If a reasoning model writes a draft inside `<think>` that contains
  `<replacement>…</replacement>` and then gives the final answer, the draft
  wins. Should it take the last match? The test at `test_prompt.py:19` only
  covers a think block without tags.
  11. Prompt injection and delimiters: if the document itself contains the
  literal text `<selection>` or `</selection>`, the model sees ambiguous
  boundaries (`prompt.py:32`). Has this been considered (escaping, unique
  delimiters)?
  12. Refine turns only replay `<replacement>` as the assistant message, without
  `<reason>` (`prompt.py:44`). The follow-up user message doesn't restate the
  format. Do small models then drop the tags on turn 2 or later?
  13. Why temperature 0.4 hard-coded, and no `max_tokens` (`llm_client.py:50`)?
  How is cost controlled when every refine round resends up to 200k chars of
  context?
  14. The free-model rate-limit story: the 429 message says "pick another
  model". Do OpenRouter's "busy upstream" errors really arrive as 429, or
  sometimes as 502/503, which then show a generic "provider failed (HTTP 503)"?

  **Frontend state and CodeMirror**
  15. `lockSuggestionRange` (`suggestionField.ts:195-198`) returns `[from,to]`
  to suppress changes. What exactly happens to a transaction that spans the
  range? The changes are partially dropped, not rejected. For example, Ctrl+Z of
  an earlier whole-document restore while a suggestion is open: is the undo
  then partially applied and the document left mixed?
  16. Does an insertion exactly at `from` or `to` count as "touching" the locked
  range? The comment at line 59 assumes edge typing works.
  17. Cancelling a request (Esc / Cancel) only bumps `latestRequestId`
  (`useSuggestion.ts:194`). The axios request isn't aborted, so free quota is
  still spent. Why no `AbortController` / `signal`?
  18. The model picker stays enabled while a suggestion is open, and `run` uses
  the current `model` (`useSuggestion.ts:96,108`). So a refine or retry can
  silently switch models in the middle of a suggestion. Is that intended?
  19. Global shortcuts listen in the capture phase
  (`useSuggestionShortcuts.ts:42`). Ctrl+Enter inside the refine input accepts
  all instead of submitting the refine, and Esc there applies the accepted

  How to use it: start the backend and open http://localhost:8000/usage. For
  each feature (improve, shorter, formal, custom, refine) and each model, it
  shows:
  - the number of requests
  - prompt, completion and reasoning tokens
  - the cost in USD
  - the average tokens and cost per request

  Every AI call also writes a log line with the same numbers and the feature.

  How it works:
  - The frontend tells the backend which action started each call.
  - The backend reads the token counts and the cost that OpenRouter already
    returns with every answer.
  - The usage is recorded before the answer is parsed, because a broken answer
    still spends tokens. Failed calls (rate limit, timeout) are not counted.
  - The totals live in memory and reset when the server restarts. OpenRouter's
    Activity page keeps the full history.
